# Sharkord Native Client

Устанавливаемые оболочки для существующего интерфейса Sharkord: Windows и macOS. Клиенты работают с любым совместимым сервером, а не только с одним доменом. Android не входит в этот проект.

macOS использует SwiftUI и системный WebKit. На macOS 26+ панель сервера использует настоящий `glassEffect`, на macOS 14–15 применяется системный материал. Дополнительное оформление внутри WebView включается только в Mac-приложении. Motion отвечает за переходы и реакции элементов, Anime.js за последовательность появления логотипа; свойства разделены, `prefers-reduced-motion` учитывается. Веб-клиент на сервере не меняется.

Windows использует WPF и системный WebView2. Закрытие окна сворачивает приложение в трей; завершение через «Выход» останавливает голос. На Mac закрытие окна скрывает его, завершение выполняется через ⌘Q. Смена сервера, перезагрузка и выход запрашивают подтверждение при активном захвате микрофона, камеры или экрана.

## Подключения

Введите HTTPS-адрес сервера, включая подпуть, если он есть: `https://chat.example.com/voice/`. Адрес без схемы получает `https://`, завершающий `/` добавляется автоматически. Сохраняются десять недавних подключений. HTTP разрешён для локальной разработки на localhost.

Профили WebKit/WebView2 разделены по полному нормализованному URL, включая подпуть. Куки, localStorage, выбор темы и автоматический вход одного сервера не передаются другому. Пароли приложение самостоятельно не читает и не хранит. Экран входа и чата загружается с выбранного сервера, поэтому интерфейс обновляется вместе с сервером.

Нативный мост доступен только главному фрейму выбранного сервера. Он передаёт состояние темы и захвата, а также уведомления после выдачи разрешения. Он не предоставляет удалённой странице команды запуска процессов, чтения файлов или установки обновлений. Внешние ссылки открываются системным браузером. Для OIDC разрешена цепочка HTTPS-переходов входа; на страницах провайдера нативный мост не активируется.

Язык системной оболочки русский; встроенный интерфейс Sharkord сохраняет свой переключатель языков.

## Сборка

Из корня репозитория:

```sh
bun install --frozen-lockfile
bun run --filter '@sharkord/native' build
```

macOS, Xcode 26+ и Swift 6:

```sh
cd apps/native/macos
swift test
cd ..
bun run build:macos
```

Результат: `apps/native/dist/Sharkord.app` и `Sharkord-macos-universal.zip`, универсальная сборка для Intel и Apple Silicon. Приложение подписывается локально, без сертификата Developer ID и нотарификации. Первый запуск описан в [инструкции к релизу](RELEASE.md).

Windows, .NET 10 SDK:

```powershell
dotnet run --project apps/native/windows-tests -c Release
dotnet publish apps/native/windows/Sharkord.csproj -c Release -r win-x64 --self-contained true -o apps/native/dist/windows
Compress-Archive -Path apps/native/dist/windows/* -DestinationPath apps/native/dist/Sharkord-windows-x64.zip
```

WebView2 Runtime нужен на компьютере пользователя. Клиент не включает отдельную копию Chromium.

## Выпуски и обновление

Версия задаётся в `client-config.json`; при изменении синхронизируйте `package.json`, `macos/Info.plist` и `windows/Sharkord.csproj`. Тег `client-v<version>` запускает workflow [Native Clients](../../.github/workflows/native-clients.yml), который собирает обе платформы, проверяет политики URL и обновлений, создаёт SHA-256-манифест и публикует файлы в GitHub Releases. Эти релизы не помечаются как latest, чтобы не заменять серверный выпуск в `/releases/latest`.

Кнопка «Обновления» / «Проверить обновления…» ищет стабильные клиентские теги `client-v*` в `whysoidle/sharkord`. Настройки выбранного сервера не могут изменить источник. Версии сравниваются численно; архив скачивается по фиксированному имени платформы, проверяются размер, SHA-256 и версия внутри приложения. На Mac дополнительно проверяется подпись bundle. После подтверждения помощник ждёт завершения процесса, устанавливает новую сборку и запускает приложение. Предыдущие файлы сохраняются для восстановления. Профили остаются в пользовательском каталоге данных.

Манифест и архив передаются через HTTPS из одного GitHub-репозитория. Это проверка целостности опубликованной сборки; отдельной подписи релизного манифеста сейчас нет.

## Проверки

`swift test` проверяет URL, ограничения origin/подпути, идентификаторы профилей, версии и манифесты. `windows-tests` проверяет аналогичные политики без запуска Windows UI. Playwright-тесты `native-shell.pw.ts` проверяют нативный мост, уведомления, захват синтетического потока, отсутствие оформления в вебе и reduced motion.

Mac-приложение поддерживает диагностический запуск без пользовательского профиля:

```sh
Sharkord.app/Contents/MacOS/Sharkord --smoke-test /tmp/sharkord-report.json --smoke-url https://your-server.example/voice/
```

Он открывает только публичный экран входа во временном WebKit-профиле, проверяет мост и доступность Opus/WebRTC, сохраняет отчёт и изображение интерфейса, затем завершает приложение. Он не входит в аккаунт и не запрашивает реальный микрофон. Видеосвязь, демонстрация экрана и голос между физическими устройствами требуют отдельной проверки на соответствующих ОС.

Для проверки размещения экрана входа добавьте `--smoke-layout`:

```sh
Sharkord.app/Contents/MacOS/Sharkord --smoke-test /tmp/sharkord-layout.json --smoke-url https://your-server.example/voice/ --smoke-layout
```

Этот режим переключает системную, тёмную и светлую темы во временном профиле,
изменяет размер окна и входит в настоящий полноэкранный режим. JSON-отчёт
содержит результат `passed`, размеры WebView и координаты формы для каждого
варианта. В версии 0.1.1 WebView размещается в отдельном контейнере AppKit,
который заполняет доступную область SwiftUI и изменяет размер вместе с окном.
